# Final Demonstration Checklist

**Project:** AI-Powered Government Scheme Recommendation System  
**Dataset:** 62 Live Tamil Nadu Schemes (Real Government Welfare Data)  
**Database:** Supabase PostgreSQL with Strict Row-Level Security (RLS)  
**Evaluation Engines:** Deterministic Eligibility Engine (Rule-based) + AI Recommendation Engine (LLM Relevance Scoring)  

---

## Complete 26-Step Demonstration Sequence

| Step # | Demonstration Step | Page / Component | User Action | Expected Result | Demonstrated Feature & Architectural Invariant |
| :---: | :--- | :--- | :--- | :--- | :--- |
| **1** | **Application Landing** | Home / Landing Page (`/`) | Navigate to root URL `http://localhost:5173/`. Observe hero section, feature cards, and statistics. | Clean UI loads without authentication; shows system purpose, statistics (62 Tamil Nadu schemes loaded), and action buttons. | Public access, modern responsive layout, zero private data exposure before login. |
| **2** | **Citizen Registration** | Register Page (`/register`) | Enter full name, valid email, and secure password ($\ge 6$ chars); click **"Create Account"**. *(Note: Use a temporary test account; credentials are not stored in project files.)* | Account is provisioned in Supabase Auth; redirect to Login or auto-login with session token stored in memory/localStorage. | Secure authentication integration with Supabase Auth (`supabase.auth.signUp`), password hashing. |
| **3** | **Citizen Login** | Login Page (`/login`) | Enter registered credentials; click **"Sign In"**. *(Note: Use a temporary test account; credentials are not stored in project files.)* | User is authenticated; JWT access token received; navigation bar updates to show citizen name, profile avatar, and logout option. | JWT session persistence, React `AuthContext` state synchronization, protected route access. |
| **4** | **Complete Citizen Profile** | Citizen Profile (`/profile`) | Enter Age (e.g. `19`), Gender (`Female`), Annual Income (`₹1,20,000`), Occupation (`Student`), Education (`Higher Secondary`), Category (`General`). | Profile form accepts demographic parameters with interactive input validation. | Citizen profile data model, schema validation, zero permissive database overrides. |
| **5** | **Select State = Tamil Nadu** | Citizen Profile (`/profile`) | Click State dropdown; select **"Tamil Nadu"** (`state_id = 23`). | Dropdown updates; triggers dynamic district fetch for state ID 23. | Geographic hierarchy mapping; authoritative Tamil Nadu state binding (`id = 23`). |
| **6** | **Select District** | Citizen Profile (`/profile`) | Click District dropdown; select **"Chennai"** or **"Coimbatore"**; click **"Save Profile"**. | Toast notification: *"Profile updated successfully"*; database row in `user_profiles` is upserted. | Cascading foreign-key district lookup (`/api/districts?state_id=23`); RLS restricts writes strictly to `auth.uid() = id`. |
| **7** | **View Recommendations** | Recommendations (`/recommendations`) | Click **"Recommendations"** in navbar or click the prompt pill *"Higher education assistance"*. | Recommendation list loads after deterministic filtering; qualified schemes render in grid cards. | Two-stage pipeline: Geographic pre-filtering (Tamil Nadu + Central) followed by deterministic eligibility verification. |
| **8** | **Show Eligibility Status** | Scheme Card / Recommendation View | Observe badges on displayed scheme cards. | Cards clearly display eligibility status: `ELIGIBLE` (🟢 Green), `POSSIBLY_ELIGIBLE` (🟡 Yellow). | Three-state deterministic evaluation logic: Never guesses or estimates statutory qualifications. |
| **9** | **Explain Why Citizen is Eligible** | Eligibility Breakdown Modal / Card Details | Click **"View Eligibility Criteria"** on a matching scheme. | Modal displays criteria checklist (Age: PASS, Gender: PASS, State: PASS, Income: PASS) with statutory statutory requirements. | Full explainability; citizen can inspect exact reasons why each rule was satisfied. |
| **10** | **Show a NOT_ELIGIBLE Example** | Recommendations / Search Filter | Test with a scheme requiring male gender or elderly age (e.g. *Indhira Gandhi National Old Age Pension*). | Status displays `NOT_ELIGIBLE` (🔴 Red) with explicit rejection reason: *"Citizen age (19) is below the minimum required age of 60"*. | Strict fail-fast evaluation: Incompatible statutory criteria reject immediately without false hopes. |
| **11** | **Show POSSIBLY_ELIGIBLE / Verification-Required** | Recommendations Page (`/recommendations`) | Scroll to section: **"⚠️ Schemes Requiring Demographic Verification"**. | Displays schemes where statutory clauses (e.g., landholding proof, single-girl child, departmental certificates) require manual verification. | Graceful uncertainty handling: Schemes with unparsed or non-demographic conditions are never falsely rejected or falsely approved. |
| **12** | **Match Score Separate from Eligibility** | Scheme Card Header | Observe the **Match Score** (e.g. `85% Match`) displayed adjacent to the `ELIGIBLE` badge. | Score represents multi-factor relevance/fit (0–100), distinctly decoupled from legal qualification. | **Critical Rule C:** Match score indicates prioritization/relevance, NEVER legal eligibility percentage. |
| **13** | **Open Scheme Details** | Scheme Details Page (`/schemes/:id`) | Click **"View Full Details"** on any scheme card (e.g. *Moovalur Ramamirtham Ammiyar Scheme*). | Detailed scheme view loads with comprehensive description, administering ministry/department, and overview tags. | Endpoint `GET /api/schemes/{id}` joins schemes, eligibility, documents, and sources in a single query. |
| **14** | **Show Benefits** | Scheme Details (`/schemes/:id`) | Scroll to **"Scheme Benefits & Financial Assistance"** section. | Displays structured textual and monetary benefits (e.g., monthly stipend, seed subsidy, equipment loan). | Provenance-checked benefit parsing from verified government gazette sources. |
| **15** | **Show Documents** | Scheme Details (`/schemes/:id`) | Inspect **"Required Application Documents"** list. | Displays document names accompanied by badges: `Mandatory` (Blue) or `Requirement Unspecified` (Neutral). | **Critical Rule F:** Ambiguous document requirements in source data are never falsely asserted as mandatory. |
| **16** | **Show Application Procedure** | Scheme Details (`/schemes/:id`) | Scroll to **"Application Process & Guidelines"**. | Detailed step-by-step instructions for Online/Offline application procedures are displayed. | Transparent civic guidance derived from verified MyScheme data. |
| **17** | **Show Activity / Deadline Information** | Scheme Details (`/schemes/:id`) | Check **Deadline & Application Status** badge. | Displays `Open / Ongoing` (`NO_DEADLINE`) or specific urgency flags (e.g. `Urgent: Closing Soon`). Unconfirmed schemes show `No Deadline Specified`. | **Critical Rule D & E:** `NO_DEADLINE` does not automatically mean `OPEN`; unconfirmed evidence yields `UNKNOWN`. |
| **18** | **Show Official Government Link** | Scheme Details (`/schemes/:id`) | Click **"Visit Official Portal"** button. | Link opens in a new tab directing strictly to a verified `.gov.in` or `.nic.in` portal with `rel="noopener noreferrer"`. | **Critical Rule G & H:** Anti-phishing invariant; third-party aggregator links are excluded from official action buttons. |
| **19** | **Save / Bookmark Scheme** | Scheme Details or Scheme Card | Click the **Bookmark / Save** icon (🔖). | Bookmark icon fills; toast notification: *"Scheme saved to your profile"*. | Endpoint `POST /api/saved-schemes/{id}`; user-isolated bookmarking stored in `saved_schemes` table. |
| **20** | **Open Saved Schemes** | Saved Schemes Page (`/saved-schemes`) | Navigate to **"Saved Schemes"** in the top navigation bar. | The bookmarked scheme appears in the user's personal saved library with current activity status. | Real-time state synchronization; user can track and review bookmarked schemes at any time. |
| **21** | **Show Notifications** | Notifications Page (`/notifications`) | Click the **Notification Bell** icon in the navbar. | Notifications view renders deadline alerts, upcoming application cutoffs, and scheme updates with unread badges. | Automatic deadline monitoring and time-decay classification (`URGENT`, `APPROACHING`). |
| **22** | **Open Chatbot** | Floating Assistant / Chat Widget (`/chat`) | Click the **"Scheme Assistant"** floating widget in the lower right corner. | Chat dialog opens with conversational greeting and suggested prompt pills. | Conversational AI interface powered by GPT-4o-mini / NLP pipeline with deterministic guardrails. |
| **23** | **Ask an English Scheme Question** | Chat Widget | Type: *"I am a college student in Tamil Nadu. What education schemes can I apply for?"* and press Enter. | Chatbot identifies user profile context, queries the recommendation service, and responds in English with qualified schemes. | Context-aware natural-language parsing, semantic search, and zero hallucination of eligibility. |
| **24** | **Ask a Tamil Scheme Question** | Chat Widget | Type: *"நான் தமிழ்நாட்டில் படிக்கும் மாணவி. எனக்கு என்ன கல்வி உதவித்தொகை கிடைக்கும்?"* | Chatbot detects Tamil language, retrieves eligible schemes, and responds in grammatically correct Tamil. | Multilingual cross-lingual NLP; bridges accessibility barriers for native language speakers. |
| **25** | **Show Chatbot Using Profile / Eligibility Logic** | Chat Widget | Observe scheme recommendations provided by the chatbot. | Recommended schemes strictly match citizen's age, gender, and state; chatbot does NOT mutate the profile. | **Critical Rule I & J:** Chatbot is a stateless inquiry pipeline reusing the deterministic eligibility engine. |
| **26** | **Logout and Login Again** | Top Navigation Bar | Click **"Sign Out"**; verify redirect to landing page; click **"Sign In"** and log back in. | All profile data, saved schemes, and notifications are immediately restored. | Clean session teardown and stateless token-based re-authentication with database persistence. |
